# Заметки по печати

## Как оператор физически получает распечатки

**Docker-контейнер не видит принтеры пользователя** — это принципиальное свойство архитектуры. Печать всегда идёт через **браузер оператора**:

```
[Сервер: генерит PDF]  →  [Браузер оператора: скачивает PDF]  →  [Диалог печати браузера]  →  [Принтер оператора]
```

Диалог печати браузера использует любой принтер, настроенный у оператора в системе: локальный USB-принтер, сетевой принтер офиса, «Печать в PDF», «Отправить в OneNote» и т.д. Настройка на сервере не требуется — принтер выбирается на машине оператора один раз (принтер по умолчанию Windows/macOS/Linux).

## Три сценария печати в приложении

### 1. Одно дело
`Печать` в drawer или иконка 🖨 в строке. Открывается вкладка с PDF всего дела (титульник + все файлы в порядке слотов + подвал КСР/NN). Ctrl+P → печать.

### 2. Один файл из дела
🖨 рядом с файлом внутри карточки дела. Открывается вкладка с PDF **только этого файла** (для xlsx — сконвертированного через LibreOffice, с подвалом КСР/NN). Ctrl+P → печать.

### 3. Пачка дел
Чекбоксы + `🖨 Печать выбранных` в bulk-баре. Сервер собирает **один PDF на весь пакет** (дела разделены титульниками, подвал `КСР/NN` считается локально в рамках каждого дела). Одна вкладка, один диалог печати.

## Ограничения синхронного пакета

Синхронная сборка на сервере:

| Дел в пачке | Время сборки | Размер PDF | Комментарий |
|---|---|---|---|
| до 20 | 5-40 сек | до 20 МБ | Работает без проблем. |
| 20-50 | 40-100 сек | 20-50 МБ | Работает, но диалог печати будет долго открываться. |
| 50-100 | 2-5 мин | 50-100 МБ | На грани комфорта, риск таймаута nginx/proxy. |
| 100-1000 | 5+ мин | 100 МБ - 1 ГБ | **Не рекомендуется** синхронной сборкой. |

Для больших объёмов есть [roadmap на v0.4](../docs/printing_notes.md#roadmap-v04) — async chunking через ARQ + SSE.

## Что даёт LibreOffice

xlsx-справка конвертируется в PDF через `libreoffice --headless --convert-to pdf`. Это сохраняет:
- Шрифты, размер, стиль (bold/italic)
- Ширину колонок, высоту строк
- Объединённые ячейки, границы, заливку
- Форматы чисел, дат, валюты
- Разбиение на страницы, ориентацию, поля

Что теряется: макросы (VBA), интерактивные элементы, некоторые сложные условные форматы (редко). Для типовой Справки о расчётах — 1-в-1 с Excel.

Fallback: если LibreOffice не установлен (например, локальный запуск без Docker) — приложение автоматически возвращается к упрощённому текстовому рендеру.

## Roadmap v0.4 — печать больших пачек

Обсуждено в исследовании (см. агент от 2026-09-01):

### Рекомендуемая архитектура

1. **ARQ** (asyncio-native task queue, Redis backend) — фоновая генерация PDF.
2. **Chunking**: пачка > 50 дел разбивается на подпакеты по 30-50.
3. **SSE** (`sse-starlette`) — прогресс на UI в реальном времени.
4. **Chrome kiosk-printing** — оператор запускает браузер ярлыком `chrome.exe --kiosk-printing --disable-scripted-print-throttling https://printsys.local` → каждый чанк открывается в скрытом iframe → `iframe.contentWindow.print()` шлёт на принтер по умолчанию **без диалога**.

Итог: один клик «Печать 500 дел» → прогресс-бар → 500 листов на выходе принтера. Без диалогов, без 500-МБ PDF, без таймаутов.

### Компоненты для v0.4

- добавить в compose контейнер `redis:7-alpine`
- добавить worker-контейнер (`arq app.tasks:WorkerSettings`)
- новый роут `POST /cases/batch/print/jobs` → возвращает `job_id`
- SSE-роут `GET /cases/batch/print/jobs/{id}/events`
- UI: модалка с прогресс-баром, кнопкой отмены
- документация: как оператору настроить Chrome kiosk-режим

### Альтернативы

- **QZ Tray** — WebSocket-агент на машине оператора, silent print без kiosk-режима. Требует Java, коммерческая лицензия для production.
- **CUPS/IPP из Docker** — сервер печатает напрямую. Работает только если сервер и принтеры в одной сети (обычно нет для распределённых оффисов).
- **ZIP архив PDF-чанков** — оператор скачивает и печатает Print Conductor'ом. Fallback, не «один клик».

## Диалог печати браузера — тонкая настройка

Чтобы диалог печати не требовал лишних кликов у оператора:

**Chrome/Edge:**
- Один раз в диалоге печати выбрать нужный принтер, лоток, ориентацию → сохраняется как дефолт для этого хоста.
- Отключить «Preview» в настройках Chrome → печать пойдёт сразу.
- Ярлык `chrome.exe --kiosk-printing http://printsys.local` — silent print на принтер по умолчанию без диалога.

**Firefox:**
- `about:config` → `print.always_print_silent = true` → печать без диалога (для kiosk-сценариев).
