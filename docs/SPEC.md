# Спецификация: Инструмент подготовки и печати судебных дел (пакеты КСР)

## Context

Пользователь работает с большим количеством судебных дел (КСР), каждое из которых состоит из разрозненных документов: Справка о расчётах по ЖКУ (xlsx), Выписка ЕГРП (pdf), Платёжное поручение ГП (pdf) и, при необходимости, другие. Файлы приходят в одну или несколько сетевых папок с шаблонными именами вида `da_0003455606_10000_..._Справка о расчетах по ЖКУ...xlsx`, `dl_0003455606_..._Выписка ЕГРП.pdf`, `50288178_3455606_...pdf`. КСР зашит в имена файлов и присутствует в Справке как якорный документ.

Цель прототипа — автоматически объединить файлы в дела по коду КСР, дать оператору наглядно увидеть комплектность пакетов и одним действием отправить их на печать в **строго заданном порядке документов** для последующего сшивания и передачи в суд. Также нужно отслеживать даты печати и передачи в суд.

Прототип — **автономный HTML-файл** (без сервера), демонстрируется заказчику. Дальнейший перенос на полноценный сервер с БД предполагается, но не входит в скоуп этой спеки.

Целевые браузеры демо — **Chromium (Chrome/Edge)**, где доступен File System Access API.

## Зафиксированные решения

### 1. Источник файлов
- Пользователь добавляет одну или несколько **папок** через `showDirectoryPicker()` (File System Access API).
- Прототип **запоминает набор папок** между сессиями (handle-ы + права хранятся в IndexedDB). При каждом старте автоматически запрашивает у пользователя `requestPermission()` при первом доступе — иначе покажет «требуется подтвердить доступ».
- Управление списком: **добавить папку, удалить папку**; для каждой видно имя и последний скан.
- Сканирование запускается **вручную по кнопке**, рекурсивно по всем вложенным подпапкам.

### 2. Извлечение КСР и группировка в дела
- **Якорный документ дела** — файл, имя которого содержит подстроку `Справка о расчетах по ЖКУ`.
- **КСР** = первое числовое поле в имени якорного файла (обычно 10-значное с ведущими нулями), с `ltrim('0')`.
  Пример: `da_0003455606_..._Справка...xlsx` → КСР = `3455606`.
- **Прочие файлы** цепляются к делу, если в их имени встречается **любой** из двух представлений КСР: **без ведущих нулей** (`3455606`) или **с 10-значным дополнением нулями слева** (`0003455606`). Проверка — по подстроке.
- Один и тот же файл может встретиться в разных папках-источниках — см. §5 «Дубликаты».
- Ключом дела в состоянии прототипа является **нормализованный КСР** (без ведущих нулей).

### 3. Парсинг Справки (xlsx)
- Библиотека: **SheetJS (xlsx.full.min.js), встроенная inline** в HTML-файл (base64 или минифицированная строка) — без обращений в сеть.
- Извлекаются 5 полей: **Дата формирования**, **Лицевой счет**, **За период**, **Поставщик**, **Услуга**.
- Алгоритм извлечения — **поиск по лейблам**: пройти по всем ячейкам первого листа; если содержимое ячейки нормализованно совпадает с одним из известных лейблов (регистронезависимо, без завершающих `:` и пробелов), берём значение = **соседняя справа ячейка или та же ячейка, если после лейбла в ней же идёт значение**.
- Список лейблов конфигурируется в разделе «Настройки» (можно дополнять синонимами).
- Если поле не найдено — оставляется пустым и подсвечивается в карточке дела как warning (не блокирует печать).

### 4. Модель «дела»
Каждое дело — объект с полями:
- `ksr` (нормализованный, строка)
- `metadata` из Справки: `date_formed`, `account`, `period`, `provider`, `service`
- `slots[]` — массив по порядку, определённому в настройках; каждый слот содержит:
  - `slot_name`, `required` (bool), `mask` (substring/regex), `order`
  - `files[]` — реально найденные файлы, попавшие в слот (0..n)
- `is_complete` — все `required` слоты содержат ≥1 файл
- `printed_at` (date | null), `submitted_at` (date | null)
- `print_history[]` — аудит-лог всех фактов печати (даты)
- `notes` (свободная строка)

### 5. Дубликаты и неполные дела
- **Дубликат** = ≥2 файла в одном слоте одного дела. Прототип показывает **конфликт** в карточке дела; попытка печати вызывает модалку «Выбери версию» с превью имени + размера + пути.
- **Неполное дело** = отсутствует файл в обязательном слоте. В списке — статус «неполное», с раскрытием «не хватает: `<имена слотов>`».
- Печать неполного дела **заблокирована**, пока пользователь либо не добавит недостающий файл (пересканирует), либо не подтвердит явно «Печатать без `<slot>`» в модалке (флаг фиксируется в состоянии дела).

### 6. Настройки — маски документов и порядок
- **Слоты документов** — редактируемый список: `{название, подстрока или regex, обязательный?, порядок}`.
- Порядок задаётся **drag-to-reorder** и **определяет очерёдность в PDF пакета** (для сшивания).
- **Дефолтный набор:**
  1. **Справка о расчётах по ЖКУ** — маска `Справка о расчетах по ЖКУ`, обязательный
  2. **Выписка ЕГРП** — маска `Выписка ЕГРП`, обязательный
  3. **Платёжное поручение ГП** — маска `Платежное поручение`, обязательный
  4. **Прочее** — служебный слот, куда попадают файлы, не подошедшие никуда; необязательный, всегда последним.
- Файл попадает в **первый по порядку** подходящий слот (кроме «Прочее»); если ни один — в «Прочее».

### 7. Печать и генерация PDF
- **Механика:** пользователь отмечает чекбоксами дела в списке → «Печать выбранных» → прототип **последовательно** генерирует по одному PDF на каждое дело и открывает системный диалог печати для каждого. Один PDF ⇒ один диалог ⇒ один блок в лоток принтера — очерёдность документов внутри дела гарантирована.
- **Порядок внутри PDF дела:**
  1. **Титульный лист** дела: КСР, ЛС, За период, Поставщик, Услуга, Дата формирования + **опись вложений** (пронумерованный список файлов в порядке слотов).
  2. Далее — файлы в порядке слотов из настроек. Внутри одного слота (если ≥2 файла) — сортировка по имени.
- **Справка (xlsx) в PDF:** SheetJS читает лист → HTML-таблица (сохранение основных merged-ячеек и рамок) → рендер в PDF через **pdf-lib** inline (без вызова printer'а на промежуточном шаге).
- **Готовые PDF (ЕГРП, П/П):** загружаются как есть, страницы копируются в общий PDF дела через `PDFDocument.copyPages`.
- **Другие форматы** (docx/jpg/…) вне скоупа прототипа — если встретятся, попадают в «Прочее» с warning «формат не поддерживается на печать, откройте вручную».

### 8. Подвал каждой страницы (номер КСР + сквозная нумерация)
- **Настраивается в разделе «Настройки»**: «добавлять подвал» — вкл/выкл, размер шрифта, цвет (по умолчанию светло-серый RGB ≈ 0.75/0.75/0.75).
- **Формат:** `<КСР>/<NN>`, где слева КСР дела, справа — **сквозной номер листа внутри дела** (с ведущим нулём, 2 цифры минимум).
  Пример: `3455606/01`, `3455606/02`, …
- Наложение — через **pdf-lib overlay drawText** поверх готовых страниц (не изменяя контент). Позиционируется в нижнем поле, по центру, отступ ~10 мм от нижнего края.

### 9. Даты «Напечатано» и «Передано в суд»
- **«Напечатано»** — **автоматически** проставляется `today` в момент отправки на печать (по факту клика «Печать»); можно перезаписать вручную. Все факты печати пишутся в `print_history` (аудит).
- **«Передано в суд»** — **только вручную**, через кнопку/чекбокс + date picker; по умолчанию `today`.
- **Массовая простановка** «Передано в суд» по выбранным делам — отдельной кнопкой над списком.
- **Повторная печать** — молча печатает и перезаписывает `printed_at` (в history остаётся история). Никаких модалок.

### 10. Список дел и фильтры (вкладка «Дела»)
- **Столбцы:** чекбокс, КСР, ЛС, За период, Услуга, Поставщик, Комплектность (иконка), Напечатано, Передано в суд, действия.
- **Поиск** по КСР и ЛС (по подстроке).
- **Фильтры:** статус комплектности (все / полные / неполные), статус печати (все / напечатаны / не напечатаны), статус передачи (все / переданы / не переданы), услуга (dropdown), поставщик (dropdown), диапазон дат Справки.
- **Массовые действия:** «Печать выбранных», «Отметить переданными», «Снять статусы», «Удалить».
- **Открытие дела** → карточка справа/модалка: метаданные, слоты с файлами, кнопки «Печать», «Открыть файл», «Сменить версию» (для дубликатов), «Удалить дело».
- **Удаление дела** — как одиночное (в drawer), так и массовое (в bulk-bar). Confirm-диалог. Удаляет только запись в реестре: `case`-объект, статусы, `print_history`. **Файлы в папках-источниках не тронутся.** При следующем сканировании дело автоматически появится снова — но с чистым состоянием (без `printed_at` / `submitted_at`). Назначение: убрать «мусорные» или ошибочно попавшие дела, либо сбросить статус конкретного дела для повторного цикла.

### 11. Вкладка «Источники»
- Список зарегистрированных папок (имя + путь-подсказка + последний скан).
- Кнопки: **Добавить папку**, **Удалить**, **Пересканировать все**, **Пересканировать одну**.
- После скана — панель diff: «новых дел: N, пропали файлы у M дел, добавились/обновились файлы в K делах». Пользователь видит, что изменилось.

### 12. Вкладка «Настройки»
- **Слоты документов** (см. §6) — CRUD + drag-to-reorder + чекбокс «обязательный».
- **Лейблы для парсинга Справки** (см. §3) — редактируемый список синонимов на поле.
- **Подвал** (см. §8) — вкл/выкл, шрифт, цвет.
- **Титульный лист** (§7) — вкл/выкл.
- **Правило извлечения КСР** — read-only описание (regex зашит в дефолт, но при необходимости можно переопределить в advanced-панели).
- **Export/Import JSON** — кнопка выгрузки всего состояния (настройки, дела, статусы) в один файл и загрузки обратно.
- **Очистить реестр дел** — отдельная кнопка (destructive, с confirm-диалогом). Удаляет **только реестр дел**: все `cases[]` с метаданными, `printed_at`, `submitted_at`, `print_history`, флаги «печатать без обязательного». **Сохраняются**: настройки, слоты, лейблы, реестр папок-источников (с FSA-handle). После нажатия — пользователю сообщение «запустите сканирование для повторной загрузки». Назначение: быстрый пересбор реестра с нуля, если накопились артефакты или пользователь хочет чистое состояние без потери конфигурации.
- **Очистить всё** — полный сброс (настройки → дефолты, слоты → дефолтный набор, лейблы → дефолтные, папки удалены, реестр дел удалён).

### 13. Персистентность
- **IndexedDB** (через минимальную обёртку inline, например idb-keyval, встроенную в HTML) хранит: настройки, реестр папок с handle-ами, реестр дел с метаданными и статусами, историю печатей.
- **Файлы сами не хранятся** — они читаются из папок при каждом сканировании/печати (по FSA handle).
- **Резерв:** Export → JSON-файл на диск, Import → загрузка. Формат — версионированный.

### 14. Повторное сканирование
- Дела ключуются по КСР → статусы `printed_at`, `submitted_at`, `notes` **сохраняются** даже если файлы исчезли/переименовались/добавились.
- Файлы дела **перестраиваются** при каждом скане: то, что нашлось, — попадает в слоты заново.
- Статусы можно **снять вручную** (кнопка в карточке / массовая).

## Edge cases

- **Файл-lock от Excel** (`~$da_...xlsx`) — игнорируем при сканировании (маска `^~\$`).
- **КСР короче обычного** (напр. 4 цифры) — поддерживается: правило основано на позиции в имени Справки, а не на длине.
- **Одинаковый КСР в двух разных папках-источниках** — считается одним делом; файлы объединяются в общий пул слотов; если файл с одинаковым именем нашёлся в двух папках, приоритет источника определяется порядком папок в реестре (первая — победитель, вторая — помечается как дубликат-конфликт).
- **xlsx с нестандартной вёрсткой Справки** — если по лейблу поле не найдено, оставляем пустым и в UI подсвечиваем warning; пользователь может дополнить синонимы лейблов в настройках.
- **Огромный PDF** (сотни страниц) — pdf-lib работает в памяти; при пакетной печати ≥50 дел показывается прогресс-бар, обработка идёт по одному делу за раз, чтобы не забить память.
- **Отзыв разрешений FSA** — при попытке скана/чтения показываем модалку «нужно повторно выбрать папку `<имя>`».
- **Non-Chromium браузер** — на старте показываем баннер «прототип оптимизирован для Chrome/Edge; в других браузерах доступен fallback через drag-and-drop одной папки на сеанс».
- **Подвал перекрывает текст исходного PDF** — принято решение оставлять как есть (риск озвучен пользователю); при жалобе — включить в настройках отступ 3 мм (реализуемо в v1.1).
- **Титульный лист без Справки** (дело неполное, но пользователь подтвердил печать) — метаданные в титульник берутся откуда есть; пустые поля печатаются как `—`.
- **Часовая зона / даты xlsx** — Дата формирования читается как строка, если ячейка форматирована как число-дата — конвертируется по правилам SheetJS `cellDates:true`, отображается как `DD.MM.YYYY`.

## Tradeoffs

- **xlsx → HTML → PDF через SheetJS+pdf-lib** vs. открытие в Excel. Плюс — полностью автономно, один клик, одна очередь печати. Минус — потеря сложного форматирования Справки. В v1 идём этим путём; при жалобах — переход на «требовать парный PDF Справки в папке».
- **File System Access API** vs. `webkitdirectory` vs. drag-drop. Плюс FSA — запоминание папок между сессиями, live-обновление; минус — только Chromium. Целевая аудитория — операторы в офисе с Chrome/Edge, риск приемлем.
- **Ключ дела по нормализованному КСР** vs. по имени файла. Плюс — статусы переживают переименования файлов.
- **Автопростановка «Напечатано»** vs. только ручная. Плюс — не забудешь. Минус — если печать отменили в диалоге принтера, дата всё равно проставится (правится вручную).
- **PDF на дело** vs. один PDF на пакет. Плюс — гарантированная неразрывность блока в лотке. Минус — N диалогов печати.

## Открытые вопросы (за скоуп v1)

- Перенос на серверную реализацию (FastAPI+PG или другое) — отдельная спека.
- Поддержка форматов кроме pdf/xlsx (docx, doc, jpg сканы) в общем PDF пакета.
- Автоматическая интеграция с «Контакт» / АвтоКСР для получения списка дел.
- Ролевая модель (несколько операторов) и лог действий с ФИО.
- Печать пачками с выделением дел под конкретный судебный участок / подсудность.

## План реализации (high-level)

1. Каркас HTML-файла: одна страница, три вкладки (Дела / Источники / Настройки), tab-switching на vanilla JS.
2. Встроить inline библиотеки: SheetJS, pdf-lib, idb-keyval.
3. Слой персистентности (IndexedDB) с методами get/save/export/import.
4. Дефолтные настройки: 4 слота, дефолтные лейблы, дефолтный подвал.
5. Модуль работы с папками: showDirectoryPicker, хранение handle, requestPermission, рекурсивный обход.
6. Модуль парсинга: КСР из имён, Справка xlsx, раскладка по слотам, is_complete, дубликаты.
7. Diff после скана: сравнение с предыдущим состоянием, панель «что изменилось».
8. UI «Дела»: таблица с фильтрами и поиском, чекбоксы, карточка дела, действия.
9. Модуль генерации PDF: титульник, xlsx→PDF, копирование страниц, оверлей подвала.
10. Печать: последовательный window.open+print по каждому делу, автопростановка printed_at.
11. UI «Источники»: список папок, сканирование, панель diff.
12. UI «Настройки»: CRUD слотов (DnD), лейблы, тумблеры подвала/титульника, Export/Import.
13. Массовые действия: отметить переданными, снять статусы, печать выбранных с прогрессом.
14. Демо-фикстура: папка `Система печати/Документы/`, подсказка при первом запуске.
15. E2E-проверка на реальных файлах заказчика.
