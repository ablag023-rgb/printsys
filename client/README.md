# printsys-client — клиент печати судебных дел

Windows-клиент к серверу printsys (корень этого репозитория). Забирает документы дела
через сервер, конвертирует, печатает на локальный или сетевой принтер и
отчитывается серверу о факте печати.

Сервер не печатает и не собирает PDF — он индексирует хранилища S3 и отдаёт
состав дел. Печать целиком на стороне клиента: только у него есть доступ к
принтеру оператора и к установленному Excel.

## Интерфейс — один

Окно оператора (`printsys-gui.exe`) показывает **ту же страницу**, что
открывается в браузере: клиент грузит веб-интерфейс сервера в WebView2 и
добавляет то, чего в браузере быть не может — кнопку «Печать выбранных»,
очередь печати и состав дела с числом листов. Второго набора шаблонов нет,
расходиться нечему.

Элементы печати помечены классом `client-only` и в браузере скрыты. Страница
вызывает локальный Python через `window.pywebview.api.*` — список принтеров,
запуск пакета, ход печати, разбор спорных заданий.

Вход тоже один: оператор входит на обычной странице сервера, клиент забирает
из окна выданные cookie и работает под тем же сеансом. Если вход уже был (в том
числе из командной строки), клиент отдаёт сеанс окну и форма входа не
показывается вовсе.

## Как печатается дело

**Одно дело — одно задание принтера.** Документы не склеиваются в общий PDF:
внутри задания открывается один `StartDoc`, и документы отрисовываются по
очереди в порядке слотов. Порядок слотов = порядок листов, это критично —
листы сшиваются.

На каждый лист наносится подвал `КСР/NN` со сквозной нумерацией через все
документы дела: рассыпавшуюся стопку можно собрать обратно.

Справки xlsx конвертируются через Excel COM в альбомную A4 с вписыванием по
ширине — иначе Excel режет широкую таблицу по столбцам (225 страниц вместо
61 на реальном файле). Подробности и обоснования — в docstring'ах
`convert.py`.

## Очередь печати

Состояние пакета живёт в SQLite (`%LOCALAPPDATA%\printsys\queue.db`), а не в
памяти: пакет на 50 дел — это часы работы принтера, и он обязан пережить
перезапуск клиента или перезагрузку машины.

| Состояние | Значение |
|---|---|
| `QUEUED` | поставлено в пакет, ещё не отправлялось |
| `SENDING` | идёт отправка в спулер |
| `SPOOLED` | спулер принял задание, оно ещё в очереди |
| `SENT` | ушло из очереди спулера без ошибки |
| `BLOCKED` | принтер сообщил об ошибке (замятие, нет бумаги, offline) |
| `FAILED` | не удалось подготовить или отправить |
| `AMBIGUOUS` | **требует решения оператора** |
| `SKIPPED` / `CANCELLED` | закрыто вручную |

Гарантии обеспечены схемой и порядком переходов, а не аккуратностью вызова:

- `SENDING` коммитится **до** обращения к спулеру. Клиент, убитый в этом окне,
  оставляет строку в `SENDING`, и восстановление переводит её в `AMBIGUOUS`.
- **`AMBIGUOUS` никогда не печатается автоматически.** Авто-повтор дал бы
  вторую копию на 60 листов, авто-пропуск — потерянный пакет в суд. Решает
  только оператор: `printsys resolve КСР --reprint | --skip`.
- `SPOOLED`, найденное после перезапуска, считается `SENT`: `EndDoc` уже
  вернулся успешно, значит задание было принято спулером.
- Терминальные состояния при повторном запуске пропускаются — `resume` не
  печатает дважды.
- Отчёт серверу — отдельный флаг `reported`, а не побочный эффект перехода в
  `SENT`. Упавшая сеть не превращает напечатанное дело в ненапечатанное;
  недоставленные отчёты досылаются следующим запуском.

Ошибка принтера ставит на паузу **весь** пакет, а не пропускает дело: рвать
порядок нельзя.

## Командная строка

Окно закрывает повседневную работу; командная строка нужна для сценариев и
разбора неполадок (`Запустить.cmd` в каталоге программы).

```bash
printsys login                      # вход, refresh-токен в Credential Manager
printsys printers                   # список принтеров
printsys cases                      # список дел на сервере
printsys preview КСР --out p.pdf    # состав дела; --out соберёт PDF предпросмотра
printsys print КСР [КСР…]           # напечатать (без КСР — все комплектные)
printsys queue                      # состояние очереди и незавершённые пакеты
printsys resume                     # продолжить незавершённый пакет
printsys resolve КСР --reprint      # разрешить спорное задание
printsys config --printer "HP LJ"   # настройки клиента
```

Предпросмотр — единственное место, где документы склеиваются в один PDF; в
пути печати склейки нет.

## Разработка

```bash
pip install -r requirements.txt
python -m pytest -q
```

Тесты идут кроссплатформенно: `FakeBackend` воспроизводит спулер в памяти,
очередь в тестах — временный файл SQLite (не заглушка в памяти: проверяется
именно переживание перезапуска). Окно тестами не покрыто — оно тонкое, вся
логика лежит в модулях, которые проверяются напрямую.

Адрес сервера для отладки: `PRINTSYS_SERVER=http://localhost:8001`.

## Установка у операторов

Два варианта, **оба без прав администратора**:

```bash
python -m PyInstaller --noconfirm --clean printsys.spec
python packaging/build_msi.py --version 0.4.0                           # per-user MSI
python packaging/build_zip.py --server http://printsys.corp.local:8001  # ZIP без установки
```

MSI ставится в профиль без UAC:

```bash
msiexec /i printsys-0.4.0-peruser.msi /qn SERVERURL=http://printsys.corp.local:8001
```

Данные оператора (очередь печати, настройки) лежат вне каталога программы и
переживают обновление и удаление клиента.

Подробности, проверенные результаты и оговорки про SmartScreen/AppLocker —
[docs/install.md](docs/install.md).
