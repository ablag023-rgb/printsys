# Установка клиента у операторов

Два варианта, **оба без прав администратора**:

1. **per-user MSI** — обычная установка в профиль, с ярлыком в меню «Пуск» и
   записью в «Установке и удалении программ». Подходит для раздачи через
   централизованные средства.
2. **ZIP** — распаковал и работаешь, вообще без установки. Годится там, где
   MSI по каким-то причинам не проходит.

Клиенту права администратора не нужны **никогда во время работы**: печать
через `win32print`, Excel COM, Credential Manager и SQLite в профиле — всё
доступно обычному пользователю.

## Вариант 1. per-user MSI

Ставится в профиль пользователя, **UAC не запрашивает**:

```bash
msiexec /i printsys-0.5.0-peruser.msi /qn SERVERURL=http://printsys.corp.local:8001
```

| Что | Куда |
|---|---|
| `printsys-gui.exe`, `printsys.exe` + зависимости | `%LOCALAPPDATA%\Programs\printsys\` |
| `HKCU\Software\printsys\ServerUrl` | реестр пользователя |
| ярлык | личное меню «Пуск» (ведёт на `printsys-gui.exe`) |
| очередь и настройки | `%LOCALAPPDATA%\printsys\` |

Решения в [`packaging/printsys.wxs`](../packaging/printsys.wxs):

- `InstallScope="perUser"` + `InstallPrivileges="limited"` — установщик не
  поднимает UAC;
- каталог под `LocalAppDataFolder\Programs`, а не `Program Files`: туда обычный
  пользователь писать не может;
- все записи в `HKCU` — `HKLM` без прав недоступен;
- `SERVERURL` пишется **отдельным компонентом с условием**: без параметра ключ
  не создаётся вовсе, а не создаётся пустым — иначе пустая строка перекрыла бы
  значение из `printsys.json`;
- `Codepage="1251"` — без него линковщик не принимает кириллицу в названии
  продукта;
- `MajorUpgrade` — обновление ставится поверх;
- ярлык ведёт на `printsys-gui.exe` — окно оператора. На `printsys.exe` вести
  нельзя: консольная утилита отрабатывает команду и завершается, окно
  закрывается быстрее, чем его успевают прочитать. Командная строка остаётся
  доступной через `Запустить.cmd` в каталоге программы;
- иконка НЕ задаётся через `<Icon SourceFile="…printsys.exe">`: WiX встраивает
  указанный файл в установщик целиком, и MSI пухнет с 43 до 57 МБ;
- каталог данных установщик **не создаёт и при удалении не трогает**: там
  очередь печати, и снос клиента не должен уничтожать сведения о незавершённом
  пакете.

Удаление — через «Установку и удаление программ» или `msiexec /x {ProductCode}`.

### Сборка MSI

```bash
python -m PyInstaller --noconfirm --clean printsys.spec
python packaging/build_msi.py --version 0.4.0
```

Нужен WiX v3 в `tools/wix311/` — портативные бинарники
([wix311-binaries.zip](https://github.com/wixtoolset/wix3/releases/tag/wix3112rtm),
sha256 `2c1888d5d1dba377fc7fa14444cf556963747ff9a0a289a3599cf09da03b9e2e`),
распаковываются, установки не требуют.

Список файлов генерируется `heat` при каждой сборке, а не хранится в
репозитории: состав бандла PyInstaller меняется вместе с зависимостями, и
ручной список неминуемо разъехался бы с содержимым `dist`.

### per-machine вариант

Если понадобится ставить на всю машину (`Program Files`, `HKLM`, `ALLUSERS=1`)
— это отдельный `.wxs`, и он **потребует администратора**. Смысл имеет только
там, где на одной машине работает несколько операторов.

## Вариант 2. Переносимая раздача (ZIP)

Оператор получает `printsys-0.5.0-portable.zip` (~61 МБ), распаковывает,
например, в `%LOCALAPPDATA%\Programs\printsys`, запускает `Запустить.cmd` — и
работает. Ни установки, ни реестра, ни администратора. Python на машине не
нужен, он внутри.

Адрес сервера прописывается **при сборке раздачи**, в `printsys.json` рядом с
exe:

```json
{ "server_url": "http://printsys.corp.local:8001" }
```

Оператору вводить адрес не нужно. Если он потом задаст свой принтер
(`printsys config --printer "…"`), в профиль запишется **только** это поле —
адрес сервера продолжит приходить из раздачи, и его можно поменять
централизованно, просто выдав новый ZIP.

Запуск exe напрямую с сетевой шары технически работает, но плох: старт
медленный, а обновить файлы нельзя, пока хоть у кого-то клиент открыт. Лучше
раздавать ZIP, чтобы у каждого была своя копия.

## Данные оператора

Лежат в `%LOCALAPPDATA%\printsys\` (очередь печати, настройки) и в Credential
Manager (refresh-токен) — то есть **вне** каталога программы при обоих
вариантах. Каталог программы можно удалить или заменить новой версией, не
потеряв состояние незавершённого пакета.

Очередь печати **всегда** в профиле, даже когда сам клиент лежит на общем
сетевом каталоге: иначе два оператора получили бы одну очередь на двоих — чужие
дела в своём пакете и гонки за состояние. Перенести данные осознанно (например,
на флешку) можно через `PRINTSYS_DATA_DIR`.

## Откуда берётся адрес сервера

По возрастанию приоритета:

1. `HKLM\Software\printsys\ServerUrl` — per-machine установка;
2. `HKCU\Software\printsys\ServerUrl` — per-user MSI;
3. `printsys.json` рядом с exe — переносимая раздача;
4. `config.json` в профиле — выбор оператора;
5. `PRINTSYS_SERVER` — отладка.

Ни один источник не обязателен.

## Чего ждать в корпоративной сети

- **SmartScreen** при первом запуске неподписанного exe покажет предупреждение.
  Снимается подписью кода — сертификат нужен один на организацию.
- **AppLocker/WDAC**, настроенные на запрет запуска из профиля пользователя,
  заблокируют оба варианта: и MSI, и ZIP ставят exe в профиль. Лечится правилом
  на издателя (после подписи) или на каталог.
- **Антивирус** иногда придирается к свежесобранным PyInstaller-бандлам.
  Лечится подписью и исключением каталога.

## Требования к машине

- Windows 10/11 x64.
- **WebView2** — окно оператора показывает веб-интерфейс сервера. Компонент
  входит в Windows 10/11 (ставится вместе с Edge), отдельной установки обычно
  не требует. Если его нет, окно не откроется — останется командная строка.
- **Microsoft Excel** — конвертация справок xlsx идёт через Excel COM, он даёт
  вёрстку 1-в-1 с тем, что видит оператор. Без Excel клиент не падает, но
  переходит на резервный построчный рендер: содержимое сохраняется,
  форматирование теряется. Для подачи в суд это неприемлемо, поэтому Excel
  считаем обязательным.
- Установленный принтер (локальный или сетевая очередь).
- Сетевой доступ до сервера printsys по HTTP(S). Доступ к хранилищам S3 клиенту
  **не нужен** — документы идут через сервер.

## Сборка обеих раздач

```bash
pip install -r requirements.txt pyinstaller
python -m PyInstaller --noconfirm --clean printsys.spec
python packaging/build_zip.py --server http://printsys.corp.local:8001   # ZIP, 61.4 МБ
python packaging/build_msi.py --version 0.5.0                           # MSI, 60.2 МБ
```

`build_zip.py` без `--server` убирает `printsys.json` из каталога — чтобы
раздача не унесла чужой адрес с прошлой сборки.

Режим сборки one-folder, а не one-file: один exe распаковывает себя во
временный каталог при каждом запуске, что заметно на старте и упирается в
политики блокировки исполняемых файлов из `%TEMP%` — обычные в корпоративной
сети.

## Обновления

Переносимый вариант: распаковать новый ZIP поверх (клиент должен быть закрыт).
MSI: major upgrade — новая версия удаляет старую и встаёт на её место. В обоих
случаях очередь и настройки в профиле переживают обновление, схема SQLite
создаётся идемпотентно, миграция не нужна.

Перед обновлением стоит убедиться, что незавершённых пакетов нет:

```bash
printsys queue
```

## Статус

**per-user MSI проверен живьём** на этой машине от **непривилегированного**
процесса (`WindowsPrincipal.IsInRole(Administrator) = False`):

- установка `msiexec /i … /qn SERVERURL=…` вернула 0, UAC не появлялся;
- встало 126 файлов в `%LOCALAPPDATA%\Programs\printsys`;
- `HKCU\Software\printsys`: записаны `ServerUrl` и `InstallDir`;
- ярлык появился в личном меню «Пуск»;
- Windows Installer подтверждает контекст: `AssignmentType = 0` (per-user),
  `InstallLocation = C:\Users\…\AppData\Local\Programs\printsys\`;
- установленный клиент читает адрес из `HKCU`, видит принтеры и получает список
  дел с сервера;
- удаление `msiexec /x` вернуло 0: каталог программы, ярлык и ключ настроек
  удалены, **каталог данных с `queue.db` остался нетронутым**.

**ZIP-раздача проверена** отдельно: из собранного exe работают `printers`,
`health`, `cases`, `preview` (Excel COM + pypdfium2) и `queue`; порядок
источников настроек соблюдается.

запуске, а строгий AppLocker/WDAC может заблокировать запуск.
